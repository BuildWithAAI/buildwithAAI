# Public project-wallet register

**No verified project wallet is entered in this draft.** All actual addresses and control facts are **TBD — DO NOT GUESS**. This is not a claim that no wallet exists elsewhere.

Do not insert sample addresses that could be mistaken for a real payment destination. Add a row only when a real project-controlled wallet exists, control has been checked, and the owner approves disclosure. Never include secrets or undisclosed personal wallets.

| Required field for each real record | What to establish |
| --- | --- |
| Record ID and full address | Exact identity on the stated network |
| Purpose | Development, creator fees, treasury, operations, or another specified use |
| Controller | Person/entity or multisig design, with publishable control evidence |
| Restrictions | Enforced limits separately from voluntary intentions |
| Funds locked? | Evidence, lock program, expiry, and any controller override |
| Can assets be sold/transferred? | Actual technical permissions and stated operating policy |
| Allocation / balance | Units, amount, source, and observation time |
| History link | Direct explorer record matching the exact address |
| Approval and changes | Owner decision, reviewer, date, reason, prior record |

Calling a wallet a treasury does not make it community-controlled or multisig. Calling an allocation locked requires evidence. A disclosure does not authorize a transfer or create a holder entitlement.

The founder's intended use of creator fees remains in [FUNDING.md](../FUNDING.md). Exact routing, wallets, amounts, budgets, reporting cadence, and locks must be recorded only after they are actually decided and verified.

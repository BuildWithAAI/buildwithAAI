## Native GitHub Project specification

Proposed title: **Build With AAI — Community Development**. The title is a working community label, not the future blockchain name. Zoora Blockchain vs AAI Blockchain remains undecided.

| Field | Definition |
| --- | --- |
| Title / item link | Actual issue link after creation, retaining its planning ID |
| Planning ID | Unique AAI-T identifier; proposal ID can be linked separately |
| Status | Single select using all 10 states above |
| Commitment | APPROVED, IDEA, RESEARCH, FUTURE or NOT PROMISED, scoped to the item |
| Type | Primary type label from the proposed definitions |
| Priority | P0, P1 or P2 |
| Phase | 0–5; sequence is descriptive, not a date promise |
| Assignee | Only a contributor who has accepted the task |
| Dependencies | Linked tasks/issues and unresolved decisions |
| Token impact | Explicit summary; protected changes require owner review |
| Evidence / decision | Links to proposal, review, tests or release |

Suggested views: **Foundation** (P0 review table), **Work stages** (board grouped by status), **Research and ideas** (filter), and **Released outputs** (only accepted evidence-backed releases). Do not use an automatic "issue closed = released" rule; rejected and deferred items must retain their actual meaning.

Create the native project under the organization only after the process is accepted. Add selected live issues, configure fields and verify visibility. Keep decisions in the repository/issue record; update the board and status label together manually until separately approved automation exists. GitHub project creation is a separate platform action. [GitHub Projects documentation](https://docs.github.com/en/issues/planning-and-tracking-with-projects/creating-projects/creating-a-project).

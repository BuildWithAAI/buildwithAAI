# Zoora / AAI HUD: improvement backlog and changelog

Automated improvement runs (the owner wants one roughly every 15 minutes) work from this file. The routine itself is
scheduled outside this repo. This file only defines the contract.

## Contract for an improvement run
1. `.venv/bin/aai improve-lock acquire --owner <run-id> --ttl 1800`. If the exit code is 3, someone else holds the lock: **stop**.
   A lock older than its TTL is stale; `acquire` takes it over and records that in `.improve.lock`.
   A run that may go past ~20 min (full suite + guard-audit + two headless shots often does) extends its own lock with
   `.venv/bin/aai improve-lock refresh --owner <run-id> --ttl 1800` before the slow steps; refresh never takes another owner's lock.
2. Pick the **top unchecked item** below that fits in one run. Do not start large items without the owner.
3. Hard rules (never change): paper only, `place_order` returns 403, no live-order code. HUD binds 127.0.0.1 only, with no
   tunnel and no 0.0.0.0. Risk caps are 1-3% per trade, 6% total, memes 1%, perps 2%; kill at -5% day or -15% DD.
   OnePay Roth is audit-only. Voice, LLM and other agents' text never change state, and the global kill is not resumable
   from the HUD. Never read seed phrases or keys; only report whether a key is present. pump.fun 403 is shown, never bypassed.
4. Tests run against tmp DBs only (`tests/conftest.py`). **Never** smoke-test a paper idea against `data/aai.db`.
5. `.venv/bin/python -m pytest -q -m "not network"` must pass. Then `.venv/bin/aai healthcheck` and
   `.venv/bin/aai guard-audit --timeout 240` (bounded run of `/workspace/agent-guard/audit.py`).
6. Commit only your own files (other agents edit this tree too), add a changelog line below, then run
   `scripts/hud_restart.sh`, `scripts/zoora_shot_check.sh` (layout regression vs the blessed baselines; bless an intended change) and `.venv/bin/aai improve-lock release --owner <run-id>`, even if the run failed.

## Set up Zoora voice on your PC
Push-to-talk "ask anything" on the orb (aai/voice gateway, wired in aai/hud.py `/api/voice/*` + aai/static/zoora/zoora-voice.js).
1. `pip install -r aai/voice/requirements.txt` (httpx, keyring) in the HUD's Python. Without them the HUD boots and voice says UNAVAILABLE.
2. Keys go in the OS keyring, service `zoora-voice`, one slot per host: `py -m keyring set zoora-voice xai-key` (required: LLM, STT, TTS),
   `py -m keyring set zoora-voice brave-key` (optional web search). Alternatives: `tavily-key`, `openai-key`, `llm-key` / `stt-key` / `tts-key`.
3. `scripts/hud_restart.sh`, open `http://127.0.0.1:57025/`: the chip under the orb reads ZOORA VOICE · READY (else VOICE KEYS NOT SET UP;
   tap the orb to see missing slot names). `GET /api/voice/status` with `X-AAI-Token` reports slots by name only.
4. Test: `pytest -q tests/test_hud_voice.py tests/voice tests/test_zoora_voice_ui.py` (the UI file needs Playwright + Chrome).
Hard rules for future runs: voice routes never get a store/ledger/audit/command reference; context stays the allowlist in
`zoora.voice_context_from`; links render only if `https:`; all text via textContent; the mic opens only while held (60 s cap).

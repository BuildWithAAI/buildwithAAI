## Current source — AE-032.3 supervised sessions

Service 0.14.3/schema 7 adds `pilot-session` for the real-machine handoff: validate local inputs and a new private destination, run the existing read-only preflight, check credential time for the planned batch, then run the worker with identical trusted instance/agent IDs and the selected project. Optional project-filtered claims check membership and select only that agent's queued work in the same transaction. Empty selected queues never fall back to another project. Omitting the filter retains existing claim behavior. No schema migration or runtime dependency change is required.

An append-only private journal records setup, preflight, claim intent/result, saved report hashes, completion intent/result and finish. ## 0.14.2 connection binding checkpoint

Service 0.14.2/schema 7 closes the gap between a one-time preflight and subsequent worker calls. Remote `run-agent` and `work-jobs` require independently obtained instance/agent IDs; malformed or missing pins fail before network access. Every community call first makes an anonymous status request bound to the expected instance and checks the exact service version and `ZOORA_CONNECTION_BINDING_V1` protocol. The actual request carries public query preconditions. The service checks instance identity before authentication, then agent identity before records/actions, in the same SQLite transaction as the operation. Older services reject the new query parameters. A task request cannot silently cross to another instance between the probe and its mutation.

Pins propagate through claims, nested runners, check-ins, project tools, artifact declarations and exact completion retries. Direct runners check identity/authentication after inference before using a tool action or output. The probe and action share a maximum 12-second budget, shortened by the existing run deadline; OS DNS can still exceed it. A service change stops work at its next check. If settlement is refused, the report is retained when available and completion remains `UNCONFIRMED`, with no new inference or automatic requeue; the original lease may expire normally. Reports record only public binding IDs. Remote error bodies require an object and a bounded uppercase code; malformed probe errors map to a fixed identity-check failure.

Sixteen new cases exercise actual local TLS into Waitress/SQLite, two independent service databases and real worker/direct CLI child processes. They cover missing/malformed pins, wrong instance before bearer transmission, wrong agent/privileged credential, every worker request's binding, a switch after the probe before claim authentication, a switch during inference, direct tool suppression, a switch before completion, old/malformed service responses, error redaction, blank/duplicate/unpaired query pins, membership and deadlines. Model responses are explicitly **SYNTHETIC protocol fixtures**; actual hosted-model acceptance is a separate gate. Existing two-agent TLS tests now use required pins and still exercise both peer-note tools.

Local CPython 3.12.14 / SQLite 3.53.1 passes **638 tests normally and 638 under optimization**, Ruff 0.17.0, all three browser JavaScript syntax checks, Git diff checks and the existing seven-check CLI/HTTP/restart/backup acceptance. [The local verification record](evidence/ae032-connection-binding-local-verification.json) retains source/log hashes and evidence boundaries. ## AE-032.1 — supervised pilot preflight

Service 0.14.1/schema 7 adds `pilot-preflight` to address the next hardware handoff: each PC needs to verify its instance, agent, shared project and local model before claiming work. The command accepts independently supplied instance/agent IDs and a new private report path. It checks the instance, exact service version, private visibility and an actual anonymous content denial before sending the agent bearer; then checks the agent and project membership, reads local model metadata, rechecks identity/authentication and requires ten minutes of credential validity using the service clock.

The 30-second network/model budget retains the existing OS-DNS limitation. Community calls are GET-only, local model access is `/api/show` only, and the report omits notes, prompts, raw responses, credential values and filesystem paths. Unexpected remote error bodies map to fixed codes. Unsafe/existing output paths fail before a connection; subsequent readiness/transport failures retain an exclusive redacted `BLOCKED` report. A pass is a point-in-time observation and does not pin later worker connections, exercise inference or establish physical-PC/vendor-wallet acceptance. No schema migration, runtime dependency or payment/chain behavior changes.

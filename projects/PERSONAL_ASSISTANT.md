# Personal trading assistant

**Status: IDEA / PROPOSED PRODUCT DIRECTION.** No assistant service, voice interface, exchange integration, or execution feature is delivered here. Users would choose their own assistant name; no product name is locked.

## Purpose

Help people stay deliberate with money during fast-moving markets. Answer natural questions, filter overstimulation, and distinguish evidence from interpretation. Example requests include “What is the Solana meme narrative today?”, “What changed?”, and “Does this fit my plan?”

| Mode | Proposed scope |
| --- | --- |
| Pump.fun / trenching | Timestamped narrative research, token investigations, watchlists, liquidity/activity changes, uncertainty, and controlled notifications |
| Spot / leverage | Market context, user-plan review, exposure and account observations where permitted integrations exist, journaling, and post-trade review |

Text is a starting interaction; voice, delivery platform, devices, persistent sessions, providers, latency, and exchange support need separate design. Do not portray the existing scanner as the completed assistant.

## Evidence and permissions

Every market report should retain source, observation time, freshness, relevant limitations, and uncertainty. Price movement does not prove an external cause. Missing data must remain missing. Group copied claims by original source so repetition does not look like independent evidence.

Define separate access scopes for reading public data, reading private account data, alerts, preparing an order, confirming an order, and any autonomous operation. A user-selected mode or a forum message cannot expand permissions. The initial proposed milestone is research-only. No live/demo automated trading or credential collection is approved by this brief.

Preferences and journal retention need explicit user controls. Model output and external content must not override budget or action policies. Account-specific risk calculations require verified instrument/provider inputs and an accepted specification; no claim of guaranteed loss prevention is made.

## First milestone

Choose one question type and produce a compact sourced report with normal, stale, contradictory, and unavailable-data cases. Evaluate usefulness and factual support on a fixed set of tasks, within a defined operating budget. Record failures and propose tested corrections. Later integration with the [agent forum](AGENT_ECONOMY.md) could allow separately authorized specialist research requests.
